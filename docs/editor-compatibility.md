# 真实中文输入法与移动键盘验收

本协议对应 [07 工单](../tasks/07-editor-compatibility.md)。记录对象是现有受控原生 textarea 适配层，不涉及第三方编辑器替换、自动保存或存储格式变更。当前没有本协议下的真实设备操作证据，以下组合全部为 **待验证**；本文的准备工作不构成兼容性通过。

## 环境与证据约定

使用独立测试项目、临时 owner 和合成文本；按 [M1 隔离实例步骤](m1-handoff.md#精确运行与测试) 启动已迁移的实例。不要将已有 owner、真实日记、密码、cookie、CSRF 或完整 HAR 放进验收证据。保留已存在的数据，测试结束的清理另行记录具体对象及授权。

本轮专用合成实例、连接方式及测试 owner 的准备状态见 [输入法验收交接](editor-validation-handoff.md)；手工用例使用该专用实例。2026-10-26 的环境盘点观察到 macOS 27.0.1（build 26A434）、Safari 27.0.1、Chrome 155.0.8059.85。软件存在不代表候选窗口或真实输入法已验证；当前没有对应手工操作证据。设备工具中的登记记录也不代表已有连接、可交互的真机，后续应以实际连接和证据更新矩阵。

桌面可使用 loopback 测试入口。手机访问电脑的 `127.0.0.1` 不会访问到电脑：真机执行前应由环境负责人提供独立测试 HTTPS 入口及匹配的 trusted origin / Secure cookie，或已授权的私密转发入口。没有可用入口就记录环境不可用；不以公开数据库端口解决访问问题。

每个组合独立记录准确版本、日期、代码 revision 和测试者；同一系统的不同浏览器分别验证。版本或证据未知时填“未记录”，不能从另一组合推定。初次执行前记录以下命令结果，代码有本地修改时同时记录差异标识：

```bash
git rev-parse HEAD
git status --short
```

证据保存在约定的仓库外私密目录；文档只写稳定证据 ID、用例和结论。截图/录像需显示输入动作、候选窗口或软键盘及结果；不要把凭据、通知、真实内容或开发者工具中的认证头带入画面。逐字比较可用合成文本、记录 ID 和内容校验结果，不公开整库导出。

## 合成文本与比较基准

每次在正文增加唯一测试标识，例如 `IME-MAC-SAFARI-C02-<执行日期>-<序号>`，避免混淆已有测试记录。手输候选文本可使用“今天去北京，明天看海”；候选翻页时主动选择非第一页的词，并记录最终选中的文字。

以下 JSON 表示内容样本，`\n` 是换行、`  \n` 前的两个 ASCII 空格是尾空格检查。输入正文时不包含 JSON 外层字段或引号；可自行增加唯一标识。

```json
{
  "content_md": "# 真机输入法验收\n\n今天去北京，明天看海。\n中文标点：，。！？；：「」\nEnglish 123 / path_a_b 100%\nEmoji 😀🌱；组合字 é\n- Markdown 列表\n尾空格检查  \n最后一行\n",
  "entry_date": "2000-02-29"
}
```

记录保存前编辑器里实际确认的完整字符串、补记日期和保存后记录 ID。剪贴板或输入法若转换了换行，需记录实际输入结果；不要在比较时 trim、规范化 Unicode 或删除尾空格来制造一致。保存后比较列表、重新读取和修订历史；需要字节核验时使用 [只读导出格式与核验命令](export-format.md)，仅针对隔离合成库。

## C01 — 中文候选与确认键

1. 进入日记编辑器，启用本行指定的真实中文输入法。连续输入拼音，至少触发一次候选翻页；分别用空格、数字选词和 Enter 确认候选。
2. 在尚有候选窗口时退格修改拼音，再选择不同候选；记录最终文字。观察候选确认是否只提交文字，是否意外保存、丢字、重复或失焦。
3. 文字全部确认后，显式点击“保存日记”；重新读取并比较全文。再输入第二段，使用 Enter 创建正文换行，确认没有自动提交日记。

期望：composition 期间不能误保存；候选确认不重复文字，显式保存只创建一篇。若录制证据，应包含真实候选窗口/软键盘操作；也可记录测试者逐项实际操作、观察结果及原文校验，明确标注证据类型。脚本派发 composition 事件不能作为本用例的系统输入法证据。

## C02 — 混合内容、粘贴与重新转换

1. 手输中文标点后切换英文，输入 ASCII 标点、数字与 emoji；粘贴上面的多行 Markdown 样本，补足两个尾空格和最后换行。
2. 保存，重新读取，打开“修订历史”，逐字比较实际确认的正文、补记日期和 revision 1；不得执行 Markdown 中的 HTML。
3. 编辑该文并保存一次，再核对旧修订未变、新修订保持本次原文。若输入法支持 reconversion，选择已确认文本进行重新转换、换候选后保存；不支持时在结果中注明该子项的输入法能力限制。

期望：中英切换、emoji、粘贴、多行、尾空格与换行不引入非预期丢失或重复；修订原文可独立比较。不能把“不支持 reconversion”记录为已经执行通过。

## C03 — 编辑、日期与 409 冲突

1. 使用同一登录会话打开 A/B 两个标签页，两边读取同一篇合成记录后进入编辑；B 直接沿用现有 cookie，不再次登录，以免引入会话轮换。
2. A 手输一段中文、修改日记日期并保留本地草稿；B 修改正文后先保存。A 确认候选并显式点“保存修改”，得到版本冲突提示。
3. 核对 A 的完整正文、日期和冲突提示仍在；点击“读取最新版本”，对照服务器内容。仅在明确选择“保留草稿，基于新版继续”后再次保存，检查生成正确的新修订。
4. 编辑过程中打开/确认候选，再通过真实触摸或鼠标移焦到日期/历史操作，观察候选、焦点和草稿。不得在未知保存状态下刷新页面。

期望：本地草稿不会被服务器版覆盖，冲突不会自动合并或自动重试；候选/焦点变化不构成保存动作。若先遇到会话轮换导致的 403，使用“重新验证登录”恢复 CSRF 后记录并重做冲突步骤，不把 403 当成 409 通过。

## C04 — 长文、软键盘与可操作布局

1. 用多段合成文本形成至少三屏长文，在顶部、中部、末尾分别输入和修改；滚动后核对光标与编辑位置。
2. 移动真机打开/收起中文软键盘，在候选栏展开时滚动，切换横竖屏后继续编辑。检查候选栏、光标、编辑区域和保存按钮是否可见或可滚动到达。
3. 显式保存并重读全文。桌面组合执行长文与窗口缩放/滚动，记录桌面不涉及的软键盘子项。

期望：没有非预期横向溢出、无法恢复的遮挡、光标跳动造成的正文丢失或重复。桌面 Chrome 的 390×844 尺寸检查只能提供布局回归，不能替代 iOS/Android 真机结果。

## C05 — 导航、401 与显式退出

1. 输入未保存合成正文并改日期，依次切换日记→日历→归档→日记，核对完整草稿和日期。保存请求进行中时尝试切换视图，确认导航保护生效；若请求太快而无法观察，记录该子项未执行并使用隔离故障安排重测。
2. 保持 A 标签页有未保存草稿；B 标签页沿用同一 cookie 后正常退出。A 点击“重新验证登录”使其读取到 401，确认日记、日历、归档的私密内容已从 DOM 移除。
3. 在 A 原标签页重新登录同一 owner，不刷新页面，核对内存草稿可继续；登录尝试遵守共享限流，不反复快速重试。
4. 对有草稿的 A 显式退出：先取消确认，核对草稿仍在；再次选择退出并确认，重新登录后核对旧草稿与归档输入已清空。

期望：跨视图保留同页内存状态；401 先隐藏私密 DOM；同 owner 重新登录恢复草稿；明确退出按确认结果保留或清空。关闭/刷新页面后的恢复不在当前内存草稿承诺中。

## C06 — 未确认创建与固定 UUID 重试

此用例需要一次“服务端已创建、前端未收到成功结果”的可控故障。只在隔离合成实例中安排，不在正式实例断网。可复用 `JournalWorkspace.test.tsx` 的 uncertain-create 用例、`AuthGate.test.tsx` 的 401/请求 ID 回归准备故障；这些自动化本身不算真实键盘通过。

1. 在测试标签页准备一次成功响应丢弃（见下方可选故障入口），手输唯一合成文本并点保存；确认界面显示“保存结果尚未确认”。
2. 使用真实键盘/软键盘尝试更改正文和日期、切换编辑其他记录，确认请求体被冻结；可切到月历/归档再回日记，草稿与不确定状态应保留。
3. 点“重试保存”，核对重试使用相同的 `client_request_id`、正文和日期，最终列表只有一篇匹配本次标识的记录。不要在证据中保存认证头或完整 HAR；只记录两次请求的 method/path/status 与非秘密 UUID 的一致性。

期望：首个创建通常为 201、相同请求重放为 200；客户端不会生成新 UUID 或允许编辑冻结体，键盘操作不会重复创建。没有可用故障入口时本用例记录环境不可用，不凭普通断网失败推断服务端已经保存。

在允许使用开发者工具的隔离测试标签页，可安装以下一次性响应丢弃。它仍发送一次真实创建，仅在收到成功响应后向应用报告失败，不读取/打印密码、cookie 或 CSRF；完成后执行恢复函数。

```javascript
(() => {
  const realFetch = window.fetch;
  let dropNext = true;
  window.fetch = async (input, init) => {
    const response = await realFetch.call(window, input, init);
    const url = new URL(input instanceof Request ? input.url : String(input), location.href);
    const method = init?.method ?? (input instanceof Request ? input.method : 'GET');
    if (dropNext && url.pathname === '/api/v1/entries' && method === 'POST' && response.ok) {
      dropNext = false;
      throw new TypeError('Synthetic create response loss');
    }
    return response;
  };
  window.restoreLifeArchiveFetch = () => {
    window.fetch = realFetch;
    delete window.restoreLifeArchiveFetch;
  };
})();
// 本用例结束后执行：window.restoreLifeArchiveFetch();
```

远程调试不可用的设备需由测试负责人提供同等隔离故障条件；不能在本片临时安装未经授权的输入法、模拟器或网络工具。

## 自动化证据的边界

全部最低组合的关键用例有实际证据且无未解决的原文丢失/重复保存，才可宣布 task07 的兼容验收完成。若只完成设备子集，交付该子集及剩余行；没有真机证据时仅能称协议与自动化准备完成。Memos 版本/许可/React API 与同一矩阵的验证应另行决策，本片保持现有适配层。
