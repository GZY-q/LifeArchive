# 08 — 日记标签

## 范围

补齐 M1 的标签核心闭环：创建/列出标签，随日记保存标签，日记列表单标签筛选，原文修订和可移植导出保留标签。用户授权继续功能开发，并要求使用子代理、减少测试行为；本片只做必要的静态和关键行为检查，不反复执行全量回归或浏览器/恢复演练。07 的真机输入法矩阵继续待验收，不作为本片阻塞。

## 固定契约

- 新增 `0004_entry_tags`：`tags(id,user_id,name,name_key,created_at)`，owner + name_key 唯一；`entry_tags(entry_id,tag_id,user_id)` 通过复合外键保证日记和标签 owner 一致。旧修订新增 JSONB `tags`，默认 `[]`。
- 展示名首尾去空白并 NFC；唯一键 NFKC + casefold。请求名称最长 256 字符，规范化后的展示名与唯一键均为 1–40 字符；拒绝控制字符、换行和空名。
- `POST /api/v1/tags {name}`，新建 201，相同规范名称返回已有标签 200；认证、CSRF、no-store 沿用日记。响应 `{id,name,created_at}`。
- `GET /api/v1/tags?limit=100&cursor=<UUID>`，limit 1–200，按 UUID 升序，响应 `{items,next_cursor}`；只读当前 owner，不能静默截断全部目录。
- 日记创建新增 `tag_ids`，省略为 `[]`；PATCH 省略保持，`[]` 清空，拒绝 null、重复 UUID 和超过 20 个标签。无权/不存在统一 422。
- `EntryResponse.tags`、`RevisionResponse.tags` 为 `{id,name}[]`，按 UUID 排序。标签与正文、日期、revision CAS 在同一事务保存；标签单独变更也递增 revision。历史存名称快照，不修改 Markdown。创建 UUID 重放比较首次修订的正文、日期和标签集合，顺序不影响重放。
- 日记列表新增单个 `tag_id` 过滤，与日期 AND；游标绑定 tag_id（旧游标默认为 null）。不扩展归档搜索、月历计数或往年今日的筛选。
- 前端提供标签勾选/创建、列表筛选、当前和历史标签展示。标签属于草稿；保存失败、会话过期、冲突和创建重试时保留选择，冻结的创建请求不得被标签编辑破坏。
- 导出写出格式升为 v2：新增 `tags.json` 保存当前 owner 全部标签 `{id,name,created_at}`（包括未使用标签）；当前/修订 JSON 增加 `tags`。`active_only` 只限定日记，不截断标签目录；全部纳入同一只读快照和哈希清单。保留 v1 历史格式说明，不新增导入器。
- 同步恢复/导出脚本的数据字段与格式断言；本轮不执行完整恢复演练。
